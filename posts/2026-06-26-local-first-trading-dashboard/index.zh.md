# 我做交易面板时最先写的不是图表，而是“只读边界”

![本地优先、只读的交易分析面板](cover.png)

> **先说清楚：** 这是一篇软件工程文章，不是投资建议。这个项目只读、只分析、不下单、不发买卖信号。它的重点不是“预测市场”，而是“怎样做一个不会替你乱动的分析面板”。

## TL;DR

| 问题 | 我的做法 |
| --- | --- |
| 交易工具最怕越权 | 默认不连券商，连上也只读 |
| 数据看起来对但其实坏 | 失真报价直接标“勿用”，坏 IV 不算 Greeks |
| 实时数据可能收费 | UI 二次确认 + 服务端节流 |
| LLM 容易胡说 | 只把法则和事实拼进提示词，不让它下单 |
| 页面不能被慢网关冻住 | single-flight + 硬超时 + 缓存快照 |

---

## 1. 为什么先写边界，而不是先画图表

**小结论：** 交易软件里，“不会做危险动作”比“看起来高级”更重要。

我想要一块屏幕，把决策前要看的东西放在一起：

- 当前持仓。
- 延迟行情。
- 技术指标。
- 宏观背景。
- 新闻摘要。
- 自己写的交易法则。
- 一段可以丢给 LLM 的上下文。

但我给它定了一个很硬的约束：**本地优先，默认只读。**

它可以帮我整理信息、框定风险、提醒法则冲突，但不能替我下单。这个边界不是 README 里写一句“不会下单”就算了，而是要写进架构。

## 2. 误区 / 正解

| 误区 | 正解 |
| --- | --- |
| 交易面板的核心是图表 | 对我来说，核心是安全边界和数据可信度 |
| LLM 可以直接给交易建议 | LLM 只读事实和法则，不产生下单动作 |
| “只读”靠自律就行 | 只读必须由代码路径强制 |
| 数据缺了就 mock 一个 | 缺了就标缺失，不给漂亮假数 |
| 实时越多越好 | 延迟数据够用时，不主动触发付费实时源 |

## 3. 只读是设计出来的

**小结论：** 安全属性要被多个层次同时约束。

我把“只读”放在几个互相独立的地方：

| 层级 | 约束 |
| --- | --- |
| 默认状态 | 页面和轮询只用本地快照 + 免费/延迟行情 |
| 券商连接 | 只有用户显式刷新才连接 |
| 会话配置 | broker session 用 `readonly=True` |
| 代码路径 | 代码库里没有下单调用 |
| 降级策略 | 网关离线时重估旧快照，不编假数据 |

这就是我最在意的地方：**只读不是一句承诺，而是代码的形状。**

## 4. 数据诚实：宁可不好看，也别骗人

**小结论：** 一个你不能一眼信任的面板，比没有面板更糟。

我给数据可信度加了几道闸：

- 买卖价差过宽，或买价大于卖价：标记为失真，界面写“勿用”。
- 隐含波动率落在合理区间外：相关 Greeks 直接弃用。
- 期权 Greeks 拿不到：说明原因，比如“未订阅实时期权数据源”。
- 实时盘口会产生费用：必须 UI 确认，后端再节流，防止双击扣两次。
- 旧快照重估时：明确标记估值模式，比如 `live`、`snapshot_external_mark`、`snapshot_stale`。

> 我不想做一个“看起来很懂市场”的面板。我想做一个知道自己什么时候不该被相信的面板。

## 5. 技术栈：克制比堆料重要

**小结论：** 这个项目不是炫图表，而是把信息组织成可靠工作台。

| 层 | 选择 |
| --- | --- |
| 前端 | Vite + React + TypeScript |
| 后端 | FastAPI + uvicorn |
| 图表 | 没有大型图表库，主要是面板、表格、状态条 |
| 数据 | 免费/延迟行情为主，实时数据按需开启 |
| LLM | 只负责整理上下文，不拥有执行权 |

这里“不用图表库”不是因为图表不重要，而是这个工具的目标不是盯盘。它是一个**决策前的信息整理面板**。

## 6. 不靠 WebSocket 的“实时”

**小结论：** 不是所有面板都需要 socket 管线。

前端用克制的轮询：

- 几秒检查一次券商连接和组合状态。
- 更慢节奏刷新宏观和日历。
- 后端按数据源设置 TTL：报价按秒、期权按分、基本面和日线按小时、日历按天。
- 多个跨国请求用线程池并行，总耗时接近最慢的单个源。
- 全局信号量限制并发，避免免费 API 返回 429。

这套方案不酷，但很稳。对一个只读分析面板来说，稳定比“看起来实时”更重要。

## 7. LLM：只读事实，不碰按钮

**小结论：** 让 LLM 参与分析，不等于让它拥有动作权限。

我的个人法则库是一堆笔记。程序会检索相关法则，和当前持仓、行情、宏观背景一起拼成提示词。

检索管线是分层降级的：

```text
词法召回 -> 语义向量 -> 多查询扩展 -> section 扩展 -> LLM 重排 -> 全量复核
```

任何高级阶段失败，就退回纯词法检索。embedding 落盘缓存，签名包含正文哈希；法则改了，缓存自动失效。

还有一个很实用的逃生口：导出整套法则为纯文本。法则库不大时，可以直接粘进长上下文网页版 LLM，完全不依赖服务端 key。

## 8. 踩坑 / 修法

| 坑 | 表现 | 修法 |
| --- | --- | --- |
| 半开的券商网关冻住页面 | 账户/组合调用挂约 54 秒，还占着锁 | single-flight executor + 硬超时 + 返回缓存 |
| 免费数据源失效 | 页面搬家 + JS 反爬挑战 | 换数据源并处理 cookie/token 握手 |
| 期权“陈旧”误诊 | 休市时宽价差被误判为坏数据 | 加固可信度规则，不追不存在的 bug |
| 部署像 boss 战 | 缓存、stdin、SSH 参数长度、git-bash 路径转换都踩坑 | 拆部署步骤，写成 runbook |

## 9. 取舍

- 它是单用户个人工具，不是 SaaS。
- CORS 钉在 localhost，靠私网和本地环境兜底。
- 免费行情有延迟，实时数据需要付费。
- 一些第三方非官方接口随时可能变。
- 树里还有 MVP 残留，代码比 README 的部分内容更超前。
- 最重要的再说一遍：它不是自动交易，也不是投资建议。

## 10. 可复制清单

- [ ] 先定义“这个工具绝不能做什么”。
- [ ] 默认不连接高权限系统。
- [ ] 高风险数据源必须显式确认。
- [ ] 坏数据直接标坏，不显示漂亮假数。
- [ ] LLM 只读上下文，不拥有执行按钮。
- [ ] 慢外部依赖必须有超时和缓存。
- [ ] 部署也要 runbook 化。

## 11. 最后

这个项目有意思的地方，从来不是“能不能预测市场”。

它真正解决的是：

> 怎样做一个对数据诚实、对权限克制、对用户负责的分析工具。

这三件事不只适用于交易面板，也适用于任何会影响判断的 dashboard。
